## The one idea to hold onto

> **The RLHF objective (maximize reward, stay close to the reference) has an exact answer you can write down. Flip that answer around and the reward is hiding inside the policy: reward = β × log(π_θ / π_ref). Plug that into the usual "which of two answers is preferred" model and you get a plain classification-style loss on preference pairs. No reward model, no generation, no RL loop.**

---

## Where DPO sits in post-training

```
PRETRAINING ──► SFT (instruction tuning) ──► PREFERENCE TUNING ──► (often) RLVR ──► ...
                                                     │
                       ┌─────────────────────────────┴──────────────────────────────┐
                       │  Classic RLHF (lectures 3–4)        │  DPO (this lecture)  │
                       │  1. collect preference pairs        │  1. collect pairs    │
                       │  2. train a reward model on them    │  2. DPO loss on the  │
                       │  3. PPO/GRPO against the RM + KL    │     pairs, directly  │
                       └─────────────────────────────────────┴──────────────────────┘
```

Lambert's caveat: real post-training is "this complex process where you have multiple model iterations," and DPO is "just one of these tools where it can replace PPO, it can complement it." In recipes like Olmo 3, Tülu 3 and LFM2 it comes **after SFT and before (or instead of) an RL stage** (`08`).

## When does this happen? DPO's training step vs. PPO/GRPO's

The step numbers are lecture 3's: **1** sample prompts, **2** generate, **3** score, **4** reference log-probs, **5** advantages, **6** loss, **7** update.

### PPO/GRPO (online), for comparison

```
every step:  1 prompts → 2 GENERATE (slow) → 3 SCORE with RM/verifier → 4 ref log-probs
             → 5 advantages → 6 loss (ratio, clip, KL) → 7 update → next batch is generated by the NEW policy
```

### DPO (offline)

```
═══ ONCE, BEFORE TRAINING ══════════════════════════════════════════════════════════════════
  dataset of preference pairs (prompt x, chosen y_c, rejected y_r)   ← fixed; made by humans or an
                                                                       LLM judge, often from other models
  (optional) reference pass: π_ref reads every chosen and rejected     → CACHE 2 numbers per pair:
             response once (forward pass only, no sampling, no grad)     ref_chosen_logp, ref_rejected_logp

═══ EVERY TRAINING STEP ═════════════════════════════════════════════════════════════════════
                                                    policy π_θ          reference π_ref
  1. sample a batch of PAIRS from the dataset           –                     –
  2. (no generation)                                    –                     –
  3. (no scoring: the label "chosen beats rejected" is the data)
  4. reference log-probs: look up the cache          –               cached (or 1 forward pass)
  5. (no advantages, no baseline, no critic)
  6. policy forward pass on y_c and y_r               used                    –
     (teacher-forced like SFT: read the given text,
      sum the token log-probs, one number per response)
     implicit rewards = β·(policy logp − ref logp)
     loss = −log σ(reward_chosen − reward_rejected)
     loss.backward()
  7. optimizer.step()                              ★ CHANGES ★                –
→ next batch of pairs from the SAME fixed dataset (the data never depends on the current policy)
```

| | PPO / GRPO (online RL) | DPO (offline) |
|---|---|---|
| Where the text comes from | the **current policy generates it** each batch (step 2) | a **fixed dataset**, collected before training |
| Reward model / verifier | needed at step 3 | **none**: the preference label is the signal |
| Models in memory | policy, reference, reward model (+ value model for PPO): "four models" | policy (+ reference, or **just its cached log-probs**) |
| Reference log-probs | recomputed each batch, because the text is new | **computed once and cached**, because the text never changes |
| π_old, ratio ρ, clipping | yes (PPO/GRPO) | **none** |
| Advantage | reward − baseline, per completion or token | none; the "weight" `w` plays a similar role (`04`) |
| KL to π_ref | an explicit penalty, per sample, adjustable during the run | **built into the loss through β**: "static" (`05`) |
| Cost per step | dominated by generation | about **two SFT forward/backward passes** (chosen + rejected) |

*(My note: the cached reference numbers are exactly lecture 4's "anything on the fixed-data side is cached" rule. In RL, π_ref is frozen but the text is new every batch, so you recompute. In DPO both the model and the text are frozen, so one pass up front is enough.)*

## The derivation in five plain-language steps

Before any symbols. Each step says **what it's trying to achieve** and **why**.

| # | Step | What it achieves | Why bother | File |
|---|---|---|---|---|
| 0 | **Start from the RLHF goal** | "Get high reward, but don't drift far from the reference model" (reward − β·KL) | It's the same objective PPO chases by trial and error (lecture 3 `02`) | `02` |
| 1 | **Solve it exactly on paper** | The best possible policy is: *take the reference's probabilities and boost each answer by e^(reward/β), then rescale so they add to 1.* | Shows the target is known in closed form, so maybe we don't need trial and error | `02` |
| 2 | **Turn it inside out** | If the policy is "reference × boost," then the boost reveals the reward: **reward = β·log(π/π_ref) + a per-prompt constant** | Lets us read a reward *off a policy*, which is "your language model is secretly a reward model" | `03` |
| 3 | **Plug into Bradley-Terry** | The chance "A is preferred to B" depends only on reward(A) − reward(B), so the annoying per-prompt constant (log Z) **cancels** | Z is a sum over every possible response, impossible to compute. It had to disappear for this to be usable | `03` |
| 4 | **Read off the loss** | Maximize the probability of the preferences you observed: **loss = −log σ(β·Δchosen − β·Δrejected)**, where Δ = log π_θ − log π_ref | It only needs log-probs of given text, from two models. Pure supervised learning | `04` |
| 5 | **Look at the gradient** | Push chosen up, push rejected down, **weighted by how wrong the model currently is** | It's "weighted supervised learning" again (lecture 3 `01`), with the weight from the model's own mistake, not a reward model | `04` |

The slides' recap in one line: **objective → optimal policy → implicit reward → Bradley-Terry (Z cancels) → DPO loss.** Lambert: "The reward model never had to be built — it was hiding inside the policy the whole time."

## Glossary additions (new in lecture 6)

| Term | Symbol | Meaning |
|---|---|---|
| **DPO** | – | Direct Preference Optimization (Rafailov et al., May 2023): train the policy directly on preference pairs with a classification-style loss |
| **DAA** | – | Direct Alignment Algorithm: Lambert's name for DPO and its variants that train on static preference data |
| **Preference pair** | (x, y_c, y_r) | A prompt, a **chosen** (preferred) response and a **rejected** one. Also written y_w / y_l (winner/loser) |
| **Optimal policy** | π* | The exact best answer to the RLHF objective: π_ref reweighted by e^(r/β), then normalized |
| **Partition function** | Z(x) | The normalizer that makes π* add up to 1: a sum over **every possible response** to x. Impossible to compute, but it cancels |
| **Implicit reward** | r_θ = β·log(π_θ/π_ref) | The reward a policy "secretly" encodes: how much more likely it makes a response than the reference does, times β |
| **Log-ratio** | log(π_θ(y)/π_ref(y)) | Policy log-prob minus reference log-prob for the whole response. Positive = the policy likes it more than the reference did |
| **Bradley-Terry model** | p(y₁ ≻ y₂) = σ(r₁ − r₂) | Probability one response is preferred = sigmoid of the reward gap. The standard model behind reward models (lecture 2 / book ch. 5) |
| **Sigmoid** | σ(z) = 1/(1+e^(−z)) | Squashes any number into (0, 1). σ(0) = 0.5; big positive → near 1 |
| **Margin** | u | Implicit reward of chosen − implicit reward of rejected. The only thing the DPO loss looks at |
| **β (in DPO)** | β | The KL strength, carried over from the RLHF objective. Large = stay near π_ref; small = free to move (and over-optimize) |
| **Gibbs' inequality** | – | KL(p ‖ q) ≥ 0, and = 0 only when p = q. Used to read off π* |
| **Likelihood displacement** | – | The chosen response's probability **falls** during DPO even though the margin grows, because both go down and rejected falls faster |
| **Offline / online** | – | Offline: train on a fixed dataset (DPO). Online: generate fresh samples from the current policy during training (PPO/GRPO) |
| **On-policy preference data** | – | Pairs that include completions from the model you're about to tune (e.g. your SFT model) |
| **IPO, cDPO, ODPO** | – | DPO variants: squared loss to curb overfitting; label-noise smoothing; required margin |
| **ORPO, SimPO** | – | Reference-free variants: odds-ratio term added to SFT; length-normalized log-prob reward with a target margin γ |
| **Delta learning** | – | The idea that the quality *gap* between chosen and rejected matters more than which models wrote them |
